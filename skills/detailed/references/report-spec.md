# 精读报告规范

## A. 门禁失败时

严格使用来源获取协议中的短响应：以“缺少来源”开头，提供论文身份、已检查来源和需要用户上传的文件，然后停止。不要输出下列完整报告结构。

## B. 完整精读报告

### 1. 论文身份与材料完整性

- 题名、作者、期刊/平台、年份、DOI/PMID/PMCID/预印本版本；
- 同行评审/预印本/勘误/撤稿状态；
- 材料清单表：主文、主图、每类补充材料、Extended/Source Data、代码、数据、协议及其审阅状态；
- 本次精读的版本、访问日期和仍存在的缺口。

### 2. 三分钟总览

用简洁语言说明：研究问题、核心原理、研究设计、最重要结论、真正突破、证据强度和最大局限。避免提前替代后面的逐图证据。

### 3. 论文逻辑与证据链

把中心假设拆成若干主张，映射到主图、关键补充证据、方法和代码/数据。说明 Figure 1 到末图为何按这个顺序构成叙事。

### 4. 主图逐图精读

按 Figure 1、Figure 2……顺序。每张图必须作为一个 Story，并对每个可辨认子图逐项写“是什么—怎么看—看到什么—说明什么—不能说明什么—证据出处”。随后给出本图整体总结、局限及与下一图的逻辑桥梁。

不得合并跳过“相似”面板。流程示意图也要解释输入、操作、输出、假设和它如何约束后续实验。对 Extended Data 若在正式版本中属于主证据，按其实际地位处理。

### 5. 补充材料地图

逐项列出 Supplementary/Extended Figure、Table、Note、Dataset、Video 与 Source Data 的作用和关键结论。与主图直接相关的关键面板应已在对应 Story 详细解析；这里再总结它们如何加强、限定或质疑主文。

### 6. 方法、统计与代码复核

重建从样本/原始数据到最终结论的流程，覆盖实验平台、质控、预处理、模型/统计方法、对照、数据拆分、基线、消融、敏感性和外部验证。

代码审查单列：实际审阅的 commit/tag 与文件、论文—代码一致性、可安装性线索、数据/权重/配置、复现链条、license、已发现风险和未覆盖范围。未执行代码时明确写“静态审阅，未运行”，不要暗示已复现。

### 7. 整篇论文的凝练总结

依次回答：

1. 核心原理和为何有效；
2. 作者真正证明了什么，哪些仍只是提示；
3. 相对已有工作的技术/生物学增量；
4. 对领域、临床转化或研究范式的意义；
5. 可推广到哪些癌种、组织、平台或任务，前提是什么；
6. 可直接借鉴的实验设计、算法、评价体系、数据或表达方式；
7. 关键局限、替代解释、潜在偏倚和最需要的下一步验证。

### 8. 深度思考与科研突破点

给出分层建议：

- **低风险直接复用**：最小改动可用于用户课题的模块；
- **跨场景推广**：迁移到新癌种、空间平台、连续切片或多模态的条件；
- **组合式创新**：与其他方法/数据类型结合后的新问题；
- **高风险高收益假设**：最有潜力但证据最弱的方向。

每个 idea 都写证据锚点、缺口、假设、最小可行研究、关键对照、评价指标、成功标准、风险和备选方案。明确哪些是报告推演，不把它们归于作者。

### 9. 最终判断

用一段话给出论文的可信度、创新性、可复现性、可迁移性和对用户研究的综合价值；指出最值得复用的一件事和最应警惕的一件事。

### 10. 正文下载与全部资源链接

本节必须位于报告最后。按以下顺序列出并标明是否已验证：

1. 合法直接 PDF 下载；若不存在，给完整正文 HTML/官方落地页并说明无直接 PDF；
2. Supplementary Information、Extended Data 和 Source Data；
3. 官方代码仓库及固定 release/tag/commit（若有）；
4. 数据仓库、模型权重、协议和其他关键资源。

链接到具体资源，不给搜索结果页。用户上传的文件标记为“用户提供，未发现/未要求外部下载链接”。

## 写作与引用

- 默认中文，术语首次出现时附英文；图号、面板字母、基因/蛋白、模型和数据集名称保持原文。
- 事实尽量就近标注页码/章节、Fig./panel、Supplementary/Extended 编号、代码路径或直接链接。
- 用原文证据解释图，但避免大段复制原文；定量结果附比较对象、单位、样本和统计语境。
- 篇幅随图数和复杂度增长。深入不等于重复，同一事实不要在多个章节机械复述。
