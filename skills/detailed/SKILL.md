# Detailed

对一篇明确的科研论文做来源完备、逐图逐面板、可追溯到正文/补充材料/代码的深度精读。目标不是扩写摘要，而是重建证据链、论文叙事和可迁移的研究方法。

## 强制流程

1. 解析论文身份：题名、作者、DOI/PMID/PMCID/预印本 ID、版本、期刊状态及是否存在勘误/撤稿。无法唯一定位时才向用户确认。
2. 在分析论文前完整阅读 [来源获取与完整性门禁](references/acquisition-protocol.md)，先检索合法公开正文。
3. **正文门禁**：只有在用户已提供可读正文，或找到包含完整方法、结果和图注的公开全文时，才可进入精读。若只有摘要、网页预览、片段或二手解读，立即按门禁模板告诉用户“缺少来源”，列出已检查位置并请求上传 PDF；随后停止，不得输出推测性的精读报告。
4. 正文可得后，建立材料清单并收集论文实际存在的补充 PDF/表格/视频、Extended Data、Source Data、数据仓库、协议及官方 GitHub/GitLab/归档代码。论文明确引用但无法获得的关键补充材料不得静默跳过，也不得声称已全面审核。
5. 在逐图分析前完整阅读 [逐图与代码审查协议](references/figure-protocol.md)。必须视觉检查每个主图，结合图注、正文、方法、补充材料和代码逐一解释所有可辨认子图。
6. 按 [精读报告规范](references/report-spec.md) 写中文报告。报告最后一节必须给出已验证的合法正文下载链接，以及补充材料、代码和数据链接；没有直接 PDF 时说明只有何种全文入口。

## 存储与交付

- 默认在聊天中交付报告；用户要求保存文件，或任务明确需要文件交付时，再生成 Markdown 报告。
- 用户指定路径时遵循该路径；否则保存到当前授权工作区的 `outputs/detailed/YYYY/MM/<论文或方法短名>_Detailed_[非完整]精读报告.md`。年份和月份取报告生成日期；完整精读省略文件名中的 `非完整`。
- 不因本技能自动连接远程主机、上传文件或写入工作区之外的位置。远程持久化、云盘同步或外部仓库写入必须由用户明确提出，并遵循当前环境权限。
- 目标文件已存在时先比较内容或 SHA-256：内容相同则不重复写入；内容不同则保留原文件，并在扩展名前以 `_v2`、`_v3` 递增保存，禁止静默覆盖。
- 若报告依赖附图或其他交付附件，把附件放入同名资源目录，报告使用相对链接，保证归档可独立阅读。
- 保存前确认文件可完整读取且大小非零。若文件是云盘占位符、dataless 文件或内容未实体化，不得把它当作正式交付物。

## 证据纪律

- 对每项重要陈述尽量标注 `Fig./panel`、页码或章节、Supplementary/Extended Data、代码文件或数据资源。网页来源给出直接链接。
- 严格区分原始观察、作者解释、报告复核和进一步推演。不要把相关性写成因果，也不要把作者声称的“首次”直接视为事实。
- 不臆测看不清的轴、颜色、样本量、统计检验、面板标签或数值。图像或 PDF 分辨率不足时明确说明，并优先寻找高分辨率原图/源数据。
- 正文、补充材料和代码之间出现不一致时逐项记录，说明哪一个版本、页面或提交支持各说法。
- 默认用中文深入浅出地写作，术语首次出现保留英文；深度应来自证据、方法和批判性思考，而不是堆叠背景知识。

## 用户覆盖

用户可指定只读某些图、控制篇幅、接受缺失补充材料的临时报告或要求复现实验。只有用户明确接受时才可越过补充材料缺口，并必须把结果标成“非完整/临时精读”。
